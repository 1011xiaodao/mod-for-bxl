# [研究台] Research Bench — 研究系统模组开发文档（pioneer_research）

> 本文档自包含，可单独交给一个 Agent 实施，无需其他文档。
> **定位**：**整包科技总线的总闸**。独立的研究系统模组——研究树、按玩家记账的进度、科研终端方块、配方门禁条件全在这里；**不含任何殖民地逻辑**（[殖民地经营] 反向接入本模组的通道 API 来提供"组织化加速"）。

## 0. 共同背景（必读）

- 项目：「星球殖民」主题 Minecraft 整合包；本基线 **MC 1.21.1 + NeoForge 21.1.x + Java 21**，ModDevGradle 模板初始化
- 分工：**你（Agent）负责本模组全部代码/构建/调试**；项目主（人类，编程新手）负责美术资产、研究树数值设计与验收，一切汇报用中文、傻瓜式验收步骤
- 交付形态：独立 NeoForge 模组，modid 固定 `pioneer_research`，产物双端可用
- 全局约定：玩家数据持久化用 NeoForge `AttachmentType`；研究树走 datapack JSON；配置用 `ModConfigSpec`；资源命名全小写下划线；`lang/zh_cn.json` 必做；公开服务器环境，服务端权威
- 与其他自研模组：**零硬依赖**。本模组是"被依赖方"——[殖民地经营] 通过 §6 的通道 API 接入；本模组不认识任何兄弟模组
- 类名/事件名以 NeoForge 21.1 官方文档核对为准；Git 提交中文、里程碑打 tag（如 `M8.1`）

## 1. 开发方向与目标

整合包里所有科技模组的配方门禁都挂在本模组的研究完成状态上（KubeJS 条件 `research_done`）。因此本模组的第一原则：

> **不玩模拟经营、纯单人科技流的玩家，也必须能只靠本模组走完整棵"整包必需"研究树。**

**范围（本期）**：研究树 datapack 加载、按玩家记账进度（含离线推进）、科研终端方块、完成事件、KubeJS 配方条件、通道扩展 API。
**非范围**：殖民地通道的并行/加速/加成效果实现（由 [殖民地经营] 注册通道时自带）、任何具体科技内容、多人研究协作玩法。

## 2. 数据模型（按玩家记账）

- `AttachmentType<ResearchProgress>` 挂在玩家上：已完成研究集合、进行中研究（id、剩余分钟、上次推进时间戳）
- **离线推进**：与经济 tick 同频思路——按离线时长补算（补算上限默认 24h，可配），登录时一次性结算
- `copyOnDeath`：死亡不丢研究进度
- 并行数：科研终端固定 1 项；通道扩展可提高（见 §6）

## 3. 研究树（datapack JSON）

`data/<datapack>/pioneer_research/research/*.json`：

```json
{
  "id": "colony/metallurgy_1",
  "name": "基础冶金",
  "parent": "colony/root",
  "channel": "common",
  "time_minutes": 45,
  "cost": [ {"item":"minecraft:copper_ingot","count":16} ],
  "effects": {
    "unlock_building": "smelter",
    "global_bonus": {"type":"production","building_tag":"pioneer_colony:smelting","percent":10},
    "fire_advancement": "pioneer_research:metallurgy_1"
  }
}
```

- **本模组只解释**：`parent`（前置）、`time_minutes`、`cost`、`channel`、`fire_advancement`；`effects` 里的其余键（如 `unlock_building`、`global_bonus`）是**不透明数据**——本模组原样放进完成事件与查询结果，由消费方（殖民地等）自行解释与实现。**研究逻辑与效果实现分离**是本模组的边界
- `channel`：`common`（默认，双通道皆可研）/ `colony_only`（仅 colony 通道注册后可见可研，见 §6）
- 加载校验：非法条目跳过 + 日志告警；树成环/前置缺失检测，报告具体 id
- 热重载：`/research reload`（OP）

## 4. 科研终端（个人研究入口）

- 可合成方块（合成表走 datapack），放置即用，**无需殖民地**
- GUI：研究树视图（本模组实现；这套界面代码将来被 [殖民地经营] 的市政厅复用挂载，因此**接口设计留好复用点**：树渲染与进度逻辑分离）
- 流程：选研究（校验前置/通道）→ 从终端输入槽或相邻箱子扣材料 → 倒计时（按玩家数据 tick 推进，离线照常）→ 完成 → 触发进度事件 + 播放音效
- 并行 1 项；重选/取消已进行的研究退还材料（防手滑）

## 5. 整包绑定（这是本模组存在的意义）

1. **进度事件**：研究完成触发原版 advancement 触发器 → FTB Quests 任务直接引用，任务书可以整条线围绕研究树展开
2. **KubeJS 配方条件**：注册 `pioneer_research:research_done` 条件——**任何模组的任何配方**都可要求"玩家已完成某研究"才可合成/使用。**判定读玩家自己的研究记录**（终端与殖民地研究同账本）。注意这是**按玩家**语义，与 §6.1 的**存档级**物品已研究查询是同一完成事实的两个视图，选型勿混用（见 §6.1 条款 7）
3. **反向消耗**：高级研究的 `cost` 设计为科技模组产物（AE2/Mekanism 组件等），科技养殖民地
4. **红线**：任务书与配方门禁只允许引用 `common` 通道研究（保证纯科技单人可完成）；`colony_only` 的 id 出现在门禁配置中视为配置错误，加载时告警

## 6. 通道扩展 API（供 [殖民地经营] 接入，本期不写对接方）

```java
public interface ResearchApi {
    boolean isDone(UUID player, ResourceLocation researchId);
    Optional<ActiveResearch> activeOf(UUID player);          // 进行中研究
    void registerChannel(ChannelExtension extension);        // colony 启动时调用
}

public interface ChannelExtension {
    String id();                                  // 如 "colony"
    int maxParallel(UUID player);                 // 并行槽位（按市政厅等级）
    double speedMultiplier(UUID player);          // 速度乘数（研究员岗位加成）
    boolean accepts(ResourceLocation researchId); // colony_only 条件
    void onCompleted(UUID player, ResourceLocation researchId, Map<String,Object> effects); // 效果实现
}
```

- 通道未注册时：`colony_only` 研究对玩家不可见不可研；`common` 研究不受影响
- 里程碑 M8.3 用一个"测试通道"（注册一个双倍速度的假通道）验证 API 正确性，不依赖 [殖民地经营]

### 6.1 物品已研究查询契约（联调契约④，供 [物质重构仪] 接入；2026-09-06 总管裁定 + 研究台定案）

> 语义总纲（总管裁定 #28）：查询 = **存档级全局完成标记**——物品关联研究在本存档被完成（任意玩家完成或 OP 命令标记）即永久置位、全存档共享；不改变 §2「按玩家记账」底层模型，仅新增 SavedData 级全局标记 + 查询接口。拉模式（消费方自管短 TTL 缓存，本模组不推送事件）；实现须 O(1)、无主线程阻塞；软依赖，双方互不硬依赖。

**API（M8.3 随通道扩展同批交付，公开包 `pioneer.research.api`）**：

```java
public enum ItemResearchState { RESEARCHED, NOT_RESEARCHED, UNKNOWN }

public interface ResearchApi {
    // …§6 既有方法（isDone / activeOf / registerChannel）不变，以下为 M8.3 新增…

    /// 存档级权威查询（门禁一律用本三态方法）。UNKNOWN = 数据未就绪，绝不冒充 NOT_RESEARCHED。
    ItemResearchState queryItemResearch(ResourceLocation itemId);

    /// Item 便捷重载：经注册表反解为物品 id；未注册/空气物品一律 NOT_RESEARCHED。
    default ItemResearchState queryItemResearch(Item item) { … }

    /// 布尔便捷版 = (queryItemResearch(...) == RESEARCHED)；UNKNOWN → false。
    /// 仅供展示/统计，禁止作门禁唯一依据（门禁用三态版）。
    boolean isItemResearched(ResourceLocation itemId);
    default boolean isItemResearched(Item item) { … }

    /// 玩家级变体（备用）：仅该玩家本人完成才 true，语义同 isDone。
    boolean isItemResearched(UUID player, ResourceLocation itemId);
}
```

**条款**：

1. **签名兼容**：兼容 [物质重构仪] #25 两提案——`isResearched(ResourceLocation)` 主提案由本契约承接（命名定为 `queryItemResearch`/`isItemResearched`，以物品字样与研究 id 级 `isDone` 区分）；Item 重载提案以 default 重载提供（查询发生在游戏进行时、注册表已冻结，无注册时机耦合）。
2. **`unlock_items` 标准效果键**：研究 JSON `effects.unlock_items: ["minecraft:iron_ingot", …]` 由本模组解释并建立物品→研究索引；`effects` 其余键仍为不透明数据（§3 边界不变，向后兼容）。物品命中任一「已完成研究」的 `unlock_items` 即 `RESEARCHED`。
3. **三态与最早查询时机（禁止哑 false）**：数据就绪 = 存档账本（SavedData）已载入 ∧ 物品索引已构建；服务端启动完成前（无服务端 / 启动窗口期）一律返回 `UNKNOWN`，**绝不返回 NOT_RESEARCHED 冒充**（取代首轮对齐「未就绪返回 false」条款）。`/reload`、`/research reload` 的索引重建为原子换引用（volatile 快照），查询方只见旧或新完整索引、无中间态。消费方门禁协议：收到 `UNKNOWN` → 按其「研究台缺席」同款兜底策略处理（重构仪 = config 默认全解锁）并打告警日志——UNKNOWN 兜底放行与 jar 缺席兜底同类，属可接受降级。正常对局中恒就绪，UNKNOWN 仅现于启动窗口期。
4. **置位来源**：任意玩家经科研终端完成研究（§4 流程）/ OP 命令 `/research mark <research_id>`（M8.3 附带，直接置位全局标记）。标记一经置位永久生效：`/research reset`（玩家级）不影响它，也不提供单独清除命令（防误操作，需清除走删存档数据）。
5. **线程模型（2026-09-06 全项目多线程规范）**：读路径**任意线程可调**——volatile 不可变快照 + 哈希查找，O(1)、无锁、无主线程阻塞（取代首轮「请主线程调用」约束）；写路径（完成事件写入、重建结果发布）低频 copy-on-write、经主线程回投完成；账本缺失（旧存档升级首次进入）时后台线程异步重建、主线程零占用。
6. **软依赖接入**：消费方 compileOnly 单向依赖本模组 jar；运行时经 `PioneerResearch.API`（`pioneer.research.PioneerResearch` 静态字段，模组构造期赋值）调用，纯查询、无需注册时机；本模组 jar 缺席时消费方按其 config 默认全解锁，互不感知。
7. **与 §5 `research_done` 的区分（避免两套「已研究」混淆）**：§5 KubeJS 配方条件 = **按玩家**（M8.2 交付；合成时求值，读"正在合成的那名玩家"本人账本，谁合成查谁）；本契约 = **存档级**（任意玩家完成或 OP 标记即全存档共享，机器验权无玩家上下文亦可查）。二者同源不同视图：§2 玩家账本（AttachmentType）是权威底账，存档级标记是其完成事件的聚合投影 + SavedData 持久化缓存，**不反向修改**底账。选型指引：有玩家上下文的配方门禁用 §5；制卡/重构等机器验权用本契约。配方条件里若改用存档级语义，会出现"他人替你解锁配方"的越权，视为整包配置错误。

## 9. 风险与约束

- **KubeJS 条件的注册时机**：配方加载早于世界创建——条件实现必须不依赖世界/玩家实例存在，只在合成时求值
- 离线补算的边界：时间戳回退（改系统时钟）不产出负进度；补算上限防一次结算爆炸
- 效果解释权边界：本模组绝不实现 `unlock_building`/`global_bonus` 的具体效果——那是通道注册方的事；接口即边界
- 数值平衡：`time_minutes`/`cost` 全部在 datapack，禁止硬编码；配《数值速调手册》
- 研究树 GUI 将被两个模组复用，代码组织上渲染/逻辑分离，留好挂载点

# M6.6–M6.9 系统验收手册

本手册记录当前代码级验收入口。所有市场、协定和 Gauge 写操作均由服务端校验；视觉商队不参与交易账本。

## M6.6 食物链、幸福度、供暖与四季

1. 在数据包中确认存在 `pioneer_colony/cooking/*.json` 配方；当前内置面包、烤马铃薯、熟牛肉、熟鸡肉。
2. 建成农场、食堂、住宅；向殖民地缓冲提供小麦、马铃薯、生肉和煤炭。
3. 食堂必须有在岗人口。食堂按照配方的 `batches_per_minute_per_worker` 累积批次，扣除原料并将熟食写入缓冲。
4. `/colony info` 查看食物可维持天数；`/colony gauge` 查看热能存量、容量、产耗和满足率。
5. 建成锅炉房并提供燃料。默认燃料为 `minecraft:coal`，每级锅炉每游戏小时消耗 1 个，支持小数需求跨结算周期累计。无 Serene Seasons 时不燃烧供暖燃料，幸福度供暖因子固定为 0.5。
6. 安装 Serene Seasons 后，在经济结算时通过软依赖反射读取当前子季节；`heatingDemandCurve` 和 `farmSeasonOutputCurve` 配置控制供暖需求与农场产量。未安装或 API 不兼容时回退到中性模式，不应阻止模组加载。

## M6.7 星联市场

### 命令验收

- `/colony market prices`：查看数据包白名单中的行情与价格区间。
- `/colony market price minecraft:wheat`：查看单项价格。
- `/colony market book minecraft:wheat`：查看当前订单簿。
- `/colony market orders`：查看本殖民地未完成订单。
- `/colony market buy minecraft:wheat 100 2 3`：限价买入 100 个，最高 2 信用点/件，持续 3 个游戏日。
- `/colony market sell minecraft:wheat 100 2 3`：限价卖出 100 个，最低 2 信用点/件，持续 3 个游戏日。
- 价格参数为 `0` 表示市价单；时长仅支持 1、3、7、14 个游戏日。
- `/colony market cancel <订单ID>`：撤销订单，买单退回剩余信用点托管，卖单退回剩余物品；已付手续费不退。

买卖必须由殖民地总督执行，且殖民地总部正常、贸易站已建成并启用。买单预留信用点，卖单先把物品托管出缓冲；交易仅在不同殖民地/不同总督的订单之间撮合，按价格优先、时间优先和可部分成交规则处理。市价单只等待一个撮合周期，未成交部分自动撤销。

### GUI 验收

打开贸易站核心方块 GUI，切换到“星联市场”页：
- 行情表显示当前参考价、下限和上限；
- 参数栏输入物品 ID、数量、限价和时长后点击“买/卖”；
- 在订单 ID 栏填写订单编号后可撤单；
- 市场命令与 GUI 走同一服务端逻辑，不能绕过库存、余额、限价、挂单数或每日成交额校验。

市场审计日志写入存档目录下的 `logs/pioneer_colony_market.log`。价格压力每隔 `priceUpdateSeconds` 秒更新，并被数据包中的 min/max 夹住。商队仅为视觉层：只有起终点贸易站都处于已加载区块、同处主世界且满足冷却/数量限制时才会出现；商队缺席不影响成交。

## M6.8 城市间贸易协定

1. 两名玩家各自建立殖民地并启用贸易站。
2. 发起方执行：
   `/colony treaty propose <目标玩家名> minecraft:wheat 60 credits 30`
   表示每小时输出 60 小麦，按比例返还信用点。目标玩家需至少进入过服务器一次，且其殖民地数据存在。
3. 目标总督上线后执行 `/colony treaty accept <协定ID>`。邀约存于服务端 SavedData，因此发起时不要求对方在线。
4. 双方执行 `/colony treaty list` 查看状态与配额。
5. 任一方执行 `/colony treaty terminate <协定ID>`，协定进入配置指定的解约通知期，在期限内继续履约，之后自动结束。
6. 若不需要返还资源，可使用 `none 0`；若返还物品，返还比例按实际出口量结算。协定履约与市场共用每日成交额限制；路线商品产量加成由 `routeProductionBonusPerTreaty` 控制。
7. 协定交易和市场成交写入同一审计日志。商队表现不强制加载区块，不参与物资转移。

## M6.9 Gauge 与公共 API

`GaugeRegistry` 支持以 `namespace:path` 注册资源类型；热能 `pioneer_colony:heat` 是内置用例。状态包含存量、容量、产出率、消耗率和满足率，写入殖民地存档。

附属模组示例（服务端主线程调用）：

```java
ColonyApi.get().colonyOf(server, player.getUUID()).ifPresent(colony -> {
    // 每个 provider ID 覆盖自身贡献；贡献会在下次 Gauge 结算时合并并消费。
    colony.contributeGauge(
        "megaconstruct:compute_hub",
        "pioneer_colony:heat",
        500.0, // 新增热能容量
        8.0,   // 每分钟余热产出
        0.0);  // 每分钟额外消耗
});
```

`ColonyApi` 还提供缓冲读写、信用点扣款/入账、威胁值、建筑建成状态、岗位填充率、市场价格和服务端挂单入口。所有写操作必须在服务端主线程执行。

## 当前尚需整合包实测的项目

- OP 可运行 `/colony benchmark`：在内存中模拟 10 座殖民地、每座 20 栋建筑、50 轮结算，输出平均/P95/最大单殖民地耗时。该基准只测纯经济/建筑循环，不查询真实四季、协定 SavedData，也不写真实殖民地存档；它不是完整玩家/区块/TPS 负载测试。
- 真实 Serene Seasons 版本的反射 API 与季节切换验证（当前按结算周期查询，不持有编译期依赖）。
- 多客户端同服市场撮合、协定离线确认、物资容量边界与存档重启后的完整游戏内验收。
- 10 玩家 × 20 建筑的公开服 TPS/存档体积压测；当前 Gradle 构建与代码级冒烟测试不能替代真实服务器压测。
